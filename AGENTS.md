# Agent instructions

Generative Icons: native Lottie icons with Light/Strong motion and editable source, plus `generative-icons`, the Rust CLI that finds, creates, builds, checks and packages them. Read this file, then the source you are about to change.

## Repo map

| Path | What lives there |
| --- | --- |
| `crates/` | The CLI's Rust workspace; architecture, decisions and test notes in `crates/README.md` |
| `crates/generative-icons/assets/skill/` | The agent skill the CLI installs into apps (the only copy to edit) |
| `motion/icon-sets/NN-name/` | Editable icon source (`definitions.mjs`, `batches/`), set rules and evidence |
| `motion/icon-sets/library/` | Family contract, authoring kit and shared helpers |
| `prototype/icons/catalog.json` | Registered sets, in gallery order |
| `prototype/icons/NN/assets/` | Built native assets (generated by the CLI) |
| `prototype/icons/01/` | Cumulative local gallery |
| `packages/` | Web npm packages: icons, runtime, react, and the retired `lottie-icons` CLI |
| `npm/` | The `generative-icons` npm wrapper and platform packages |
| `docs/` | User, contributor and maintainer documentation |

## Commands that matter

```sh
cargo build --release -p generative-icons      # the CLI; put target/release on PATH
generative-icons context "<meaning>" --search   # from the repo root
generative-icons library new-set <slug> --name "<Name>"
generative-icons library preflight SET-ID
generative-icons library build SET-ID          # needs the user's sign-in
generative-icons library verify SET-ID && generative-icons library verify-visual SET-ID
generative-icons library register SET-ID
cargo clippy --workspace --all-targets -- -D warnings && cargo test --workspace
npm ci --prefix motion && npm test && npm run check:docs
```

Requirements, the test layout and the full library flow: [development](docs/development.md). Every CLI command: [CLI reference](docs/cli.md).

## Working rules

- One coding agent performs design, authoring, review and correction; these are stages, not separate model roles. Do not invoke another model or AI CLI unless the user asks.
- Search existing meanings first and pick relevant family neighbors. Provide complete named geometry, pivots and distinct Light/Strong motion.
- Preserve existing public icon IDs and unrelated assets. Build complete sets.
- Native export runs on LottieFiles' hosted engine and needs the user's sign-in. The hosted engine is internal until launch. On `NOT_LOGGED_IN` or `SESSION_EXPIRED`, ask the user to run `generative-icons login` in their terminal, finish the source checks meanwhile, and say which gates are still open.
- **Never run `login` or `logout` yourself, and never touch the OS keychain except through the CLI's own commands.** Tests and scripts use a temporary `GEN_ANIMATED_ICONS_HOME`, the fake keychain, or `GAI_ENGINE_TOKEN` with a local mock engine.
- Parity comes first: the CLI must reproduce the committed outputs byte for byte. Never change a committed asset or evidence file to make a test pass. The JavaScript and Python pipeline in `motion/` and `scripts/` is legacy and kept as a reference for the parity tests; do not delete it.
- Inspect rendered output between revisions (`generative-icons preview`, `library verify-visual`). Report checks you could not run; never claim a rendered review you did not do.
- Do not weaken checks to make them pass. Preserve failed evidence for diagnosis.

## Do not

- Publish packages, push tags, publish releases, deploy or change repository visibility.
- Hand-edit generated files: `prototype/icons/guide/` (run `npm run docs:build`), `prototype/icons/NN/assets/` (build the set), `packages/*/dist/` (run `generative-icons library packages`), or `skills/lottie-icons/` (frozen).
- Commit `.local/`, credentials, machine-specific paths, model transcripts or planning notes.
- Change global model or agent settings.

After changing canonical instructions or docs, run `npm run docs:build` and `npm run check:docs`.
